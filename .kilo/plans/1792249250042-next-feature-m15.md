# Plan: S2 — Habit Priority Tags

## Goal

Add a `priority` field (`critical` / `focus` / `optional`) to habits, let the user set it in create/edit, and show a small text+icon badge plus a colored left-border accent on each habit card. Priority is additive, optional, defaults to `focus`.

## Scope (one feature, one commit)

1. Schema: add `priority?: 'critical' | 'focus' | 'optional'` to `Habit` in `src/lib/db.ts` with a migration note (additive, no version bump needed — optional field).
2. Create/edit modal: priority selector (3 segmented buttons with emoji + label), default `focus`.
3. Habit card (list/grid/compact): badge (`Critical 🔴`/`Focus 🟡`/`Optional 🟢`) as text+icon, plus `border-l-4` accent color. Never color alone.
4. Normalise helper `normalizeHabitPriority(value)` returning the canonical union or `undefined` for unknown (mirrors normalizeCategory style).

## Out of scope (keep one feature)

- Energy levels and context tags (`B9` broader) — separate features.
- Filter/sort by priority, wallpaper highlights — separate features (S2 spec mentions them but they're their own items).
- Schema version bump — optional field, no migration needed.

## Data flow

- `Habit.priority` written by create/edit modals.
- Read by habit card components for badge + border.
- Unknown stored values render no badge (honest: don't invent a priority).

## Failure modes

- Unknown priority value (older backup): badge omitted, no crash.
- Missing field: defaults to `focus` in display only (not persisted) — avoids silent data writes.

## Validation

- `tsc`, `eslint src`, `vitest run`, `npm run build` clean.
- Light + dark at 360/390/430; badge text present (not color-only); reduced motion unaffected.
- New tests for `normalizeHabitPriority`.
